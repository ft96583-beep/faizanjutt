Help

How this admin panel works.

Logging in

You can sign in with your username or your full email plus your password. The username is looked up in the admin_users table and mapped to the matching Supabase Auth email behind the scenes. Manage the mapping under Admin Users.

How content is saved

  • Single-row pages (Hero, About, Contact / SEO / Identity) load one settings row and save it with an upsert — just edit the form and press Save.
  • Lists (Skills, Projects, Services, Plans, Testimonials, Blog, FAQs, Social Links, Subscribers) use Add / Edit / Delete. Deleting always asks for confirmation first.
  • Fields marked "one per line" (roles, highlights, plan features, gallery URLs) are stored as lists — put each item on its own line.

Uploads

Images and videos upload to the public media bucket in Supabase Storage and the public URL is saved automatically. Use Media Library to browse, copy URLs or delete files.

Where the site reads data

The public site reads the same tables through assets/js/db.js (with static fallback content when Supabase is not configured). Whatever you save here appears on the site after a refresh — no rebuild needed.

Analytics

The public site logs pageview and click events into analytics_events via assets/js/analytics.js. The Analytics sections here aggregate the last 30 days of events.

Backups

Use Export & Backup to download each table as JSON before making big changes. Keep a copy somewhere safe (e.g. Google Drive).

Troubleshooting

  • "Supabase is not configured" — set SUPABASE_URL and SUPABASE_ANON_KEY in assets/js/config.js and reload.
  • Save fails with a policy error — you were signed out. Log out and sign in again.
  • Login says "Username not found" — check the exact username (lowercase) in Admin Users, or sign in with the full email instead.
